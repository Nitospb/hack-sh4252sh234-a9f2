# Карточка подготовленного набора news-v1

Источник: `imports/alfa-final-dataset-2026-10-25-0900/data/training-news.jsonl`.
Снимок новостей не изменён. Собранные ранее Telegram, raw HTML, очереди
Chrome/парсера и изображения в обучение не копируются.

## Ограничения и размеры

- 7 733 исходные новости с известной датой в интервале
  `[2026-09-24T20:40:35.362238Z, 2026-10-24T20:40:35.362238Z)`.
- Нет accessible_excerpt и точных повторов text_hash, Article ID уникальны.
- Дополнительная приблизительная группировка копий исключила 77 повторных
  представлений из пар: осталось 7 656 представителей историй.
- Временные части: 6 124 / 766 / 766 историй. Из последних одна непригодна
  для title/body пары после удаления заголовка из начала тела; для слабого
  обучения остаётся 6 124 / 766 / 765 пар.
- 1 000 исходных объектных групп и их ссылки на bt_ темы сохранены.
- 1 244 задания на ручную проверку для 404 объектных групп из текущего каталога;
  они не являются 1 244 размеченными примерами. Одобренных оценок — 0.
- Telegram и изображения: 0. Набор занимает около 113 MiB.

## Разделение по времени

| Часть | Первая публикация UTC | Последняя публикация UTC |
|---|---|---|
| train | 2026-09-24 21:00:00 | 2026-10-23 16:04:18 |
| validation | 2026-10-23 16:04:36.446 | 2026-10-24 08:31:16 |
| test | 2026-10-24 08:32:00 | 2026-10-24 20:40:33 |

Сначала находится один представитель каждой группы копий, затем представители
сортируются по публикации. Границы примерно 80/10/10 по числу историй, а не
по длительности периода. Одинаковые timestamps не разрезаются границей.
Берётся самая поздняя публикация группы, остальные копии остаются в полном
news corpus и списке group_member_ids, но не в других splits.

Группировка: равенство нормализованных заголовков длиной >=40 символов либо
кандидаты MinHash-32/LSH (8 полос по 4 значения), для которых Jaccard
5-грамм тела >=0.8. Рассматриваются первые 1 500 слов. Это эвристика:
возможны пропуски перефразированных перепечаток и объединение одинаково
озаглавленных материалов. Сертифицированной семантической дедупликации нет.
Перед публичной оценкой нужна дополнительная ручная проверка пограничных
историй. Модель и метки не участвовали в расчёте временных границ.

## Файлы

| Путь внутри bundle | Содержание |
|---|---|
| manifest.json | Политики, counts, диапазоны, SHA-256 каждого файла |
| corpus/news.jsonl | Все 7 733 исходных новостных текста с устойчивыми ID/hashes/датой |
| corpus/stories.jsonl | Представители, group_id/member_ids и split |
| weak/{train,validation,test}.jsonl | query=заголовок, positive=тело без скопированного начального заголовка, supervision=weak_title_body |
| taxonomy/object_families.json | 1 000 групп, исходные IDs и семантика |
| annotation/tasks.jsonl | Pending задания с подсказкой доказательства/ссылкой; judgment=null |
| annotation/approved-labels.jsonl | Пустой список проверенных оценок на текущем этапе |
| supervised/{split}.jsonl | Будущие тройки query/positive/negative; сейчас пусто |
| supervised/{split}-qrels.jsonl | Будущие ручные оценки отдельно для каждой части; сейчас пусто |

JSONL читается физическими строками файла, не read_text().splitlines():
U+2028/U+2029 внутри текста не являются новой записью. Экранированные переводы
строк сохраняются. Префиксы query:/passage: добавляет runtime, в исходных
полях их нет. Тексты не содержат HTML-артефактов как инструкций для агента.

## Чего эти данные не доказывают

Положительная title/body пара означает связь заголовка с собственным текстом,
не полезность для конкретной компании и не наличие событийного bt_ факта.
Чужие статьи внутри contrastive batch используются как предполагаемые
отрицательные, а не как ручные оценки. Дедупликация снижает, но не устраняет
риск ложных отрицательных на похожих историях. Короткие одинаковые заголовки
внутри batch дополнительно маскируются как отрицательные.

Автоматические object/industry связи, ОКВЭД-предположения, общие операционные
интересы и пользовательские показы не преобразованы в labels. В оценке
supervised mode используются только проверенные 0/2 пары; отраслевой класс 1
сохраняется для анализа, но в loss/метрики объектной задачи не попадает.

## Воспроизводимость

Bundle immutable. Проверяй manifest перед каждым запуском. Изменившиеся
исходные новости или одобренные метки требуют новой версии output, а не
редактирования news-v1. `prepare.py` отказывается перезаписывать существующий
каталог. Исходные архивы и исходные снимки не затрагиваются.

После просмотра test результатов не используй их для выбора эпох/порогов.
Если нужна новая итерация подбора после такого просмотра, потребуется новый
независимый тест, а не переименование прежнего test в validation.
