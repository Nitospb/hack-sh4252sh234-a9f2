# Уточнения из диалога — v14.1

После проверки владельца завершённого parent-run сервис выделяет явные заявления
пользователя об условиях кредита, внешней торговле или валюте расчётов. Например:
«У нас кредит с фиксированной ставкой до2028года». Вопросы, гипотезы и пересказ
источника не сохраняются как факты. Это ограниченный детерминированный extractor,
не произвольное понимание каждого текста и не дополнительный платный LLM-вызов.

Сведения сохраняются в clarifications, исходное сообщение — в dialogue_messages.
Ключи scope: company_id + source_record_id + user. Provenance содержит message_id,
parent_run_id, точную цитату/смещение. Уровень всегда candidate, kind=user_declaration;
оно не становится банковским confirmed. Генератор должен использовать его условно.
Факты доступны в профиле и удаляются обычной кнопкой удаления уточнения.

Повтор того же сообщения с тем же parent не создаёт дубль, context_version
включает сохранённые уточнения. Условия попадают в новый анализ и последующие
анализы той же компании/пользователя. Изменение контекста инвалидирует кэш.
Только явное «Исправление: ...» заменяет единственную однозначную прежнюю
диалоговую запись той же категории; при нескольких условиях они сохраняются,
сервис сообщает об неоднозначности. Повтор того же заявления в новом parent
не заполняет память дублями; обычное новое заявление не удаляет возможный второй договор. Ручные
заметки не заменяются. Противоречие без явного исправления остаётся для условных
вариантов/одного критического уточнения. История прежних runs неизменяема.

Уточнение сохраняется при приёме валидного сообщения, даже если последующая
LLM-задача не выполнится из-за очереди/бюджета. При лимите20 заметок анализ
продолжается с прежним контекстом, а UI сообщает, что новое условие не сохранено.

Ответ включает context_change (добавленные/удалённые факты) и analysis_change
(новые/исчезнувшие формулировки, смена статуса). Это сравнение опубликованных
ответов, не доказательство причинности различий. UI показывает сведения со слов
пользователя, новые выводы и прежние формулировки. Старые ответы без полей работают.

SQLite-схема расширяется при запуске без удаления существующих строк. Перед
обновлением API выполнен online backup; все старые проверки scope/quote/schema
сохранены. Тесты: service/tests/test_dialogue.py. Живое качество языка/полноту
извлечения проверять на независимой выборке; кандидатные сведения не повышать
до confirmed ради ready.

Пользовательские fact IDs в запросе LLM заменяются короткими user_context_N.
В опубликованном ответе восстанавливаются канонические IDs. История использует
только ссылки на источники текущего запроса, не оживляет отсутствующие passages.
Ограниченная живая проверка v14: draft нарушил контракт IDs, попытка его
исправления завершилась таймаутом шлюза. Автоматических transport retries нет.
Причина ID устранена в v14.1 и проверена локальным end-to-end тестом; успешная
живая LLM-приёмка v14.1 пока не заявляется.
