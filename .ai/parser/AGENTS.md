# Инструкции для агентов, работающих с parser

Этот файл относится к `parser/` и вложенным каталогам. Он описывает действующий код и требования к его изменениям. Документация не требует наличия исходного контекста разработки или ранее собранных данных.

## С чего начать

1. Прочитай [README](README.md) — установка и пользовательские команды.
2. Прочитай [архитектуру](docs/ARCHITECTURE.md) — модули, порядок сохранения, очередь, параллелизм и ограничения.
3. При изменении полей или хранения прочитай [контракт данных](docs/DATA_CONTRACT.md).
4. При добавлении сайта используй [руководство по источникам](docs/SOURCES.md).
5. Для запуска, диагностики и проверки изменений используй [эксплуатационное руководство](docs/OPERATIONS.md).

## Назначение и границы

Это Python-сборщик финансовых, экономических, деловых и политических новостей. Приоритет — финансы и политика, примерно 60% работающих источников из России и 40% мировых. Технологии и ИИ служат дополнительным направлением. Движок общий, список сайтов задаётся конфигурацией; новые статьи внутри сайтов обнаруживаются динамически.

Исходники находятся в `news_collector/`, рабочая конфигурация — в `config/sources.json`, выключенные кандидаты — в `config/source-candidates.json`, синтетические проверки — в `tests/`. `frontend/` в корне репозитория — отдельный компонент. Не меняй его побочным эффектом работы над парсером. HTTP API, Telegram, эмбеддинги, предсказания и интеграция с фронтендом здесь пока не реализованы.

## Инварианты, которые нужно сохранить

- Новость сохраняется в SQLite **до** загрузки изображений. Отсутствие, маленький размер, ошибка фото или недоступный CDN не являются причиной удаления текста новости.
- Картинки должны иметь площадь не меньше 160 000 пикселей и короткую сторону не меньше 200 пикселей. Это ограничение площади, а не требование квадратного кадра. 400×400 и 640×360 подходят.
- Изображение связано со статьёй через `article_id`, пути относительно runtime и manifest.json. После изменения медиа обновляй также `article_images` и JSON-запись статьи через методы Store.
- Не меняй смысл `id`, `content_hash`, `text_hash` и schema_version без учёта существующих данных и потребителей.
- Не выдумывай дату публикации из времени скачивания. Дата без часового пояса остаётся неизвестной с соответствующим статусом.
- Нормализация URL статьи и обработка URL картинки различаются: параметры подписанного CDN URL нельзя переставлять или удалять.
- Браузерные операции идут через Selenium/Chrome. Используются отдельные профили источников; личный Chrome-профиль пользователя не открывается.
- Учёт robots.txt, интервалы источников, паузы, ограниченные повторы и изоляцию ошибок сохраняй при изменении планировщика.
- Не представляй отдельные успешные статьи как доказательство полного покрытия сайта. Не представляй эвристические темы как результаты ML или гарантию финансовой релевантности.

## Работа с кодом

Команды и тесты запускай из `parser/`: CLI и тесты используют относительный путь `config/sources.json`. Документированный способ установки — виртуальное окружение и `requirements.lock`. Установка wheel сама по себе не поставляет конфигурацию как package data.

Для обычной проверки используй:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Эти тесты не требуют Chrome, доступа к новостным сайтам или сохранённого корпуса. Для изменений очереди проверяй миграцию существующей БД, восстановление аренды и транзакции. Для изменений медиа проверяй сохранение текста при сбое картинки, фильтрацию размеров и сохранение связей после audit. Для изменений адаптеров добавляй содержательные синтетические проверки разметки и URL там, где они защищают от регрессии.

Изменения только документации проверяй на соответствие коду и корректность ссылок; повторный сетевой обход для них не нужен. Живую проверку адаптера делай через `check-sources` в отдельном runtime; для проверки изображений используй ограниченный `collect`. Непроверенный адаптер оставляй выключенным. Для включения требуются минимум две разные канонические статьи с проверенным основным текстом. Не запускай длительный сбор в фоне как побочный эффект тестирования.

Новые зависимости согласуй между `pyproject.toml` и `requirements.lock`, обновляй сведения о лицензиях. Не добавляй зависимости только ради замены простого существующего механизма.

## Что включать в Git

Коммить код, конфигурацию, тесты и техническую документацию. Не добавляй runtime, SQLite/WAL/SHM, новости, картинки, исходный DOM сайтов, Chrome-профили, cookies, скриншоты, логи, секреты или виртуальное окружение. Исходные материалы задания, личные промпты, экспорты чатов и контекст разработки не являются частью поставки парсера.

Не удаляй пользовательский runtime для запуска тестов. Не снимай работающую файловую блокировку удалением lock-файла. Для проверки используй отдельный каталог; для реальных изменений данных руководствуйся задачей пользователя.

## Завершение изменения

Проверь состав diff, результаты необходимых проверок и актуальность документации. В отчёте укажи, что изменено, чем проверено и какие ограничения остались. Число настроенных сайтов не равно числу включённых адаптеров, успешных загрузок или работающих фоновых процессов. Текущие числа вычисляй из конфигурации/БД, а не копируй из исторического разговора.
