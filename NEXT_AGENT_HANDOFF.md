### 4.1 Архитектура

```text
Остановленные сборщики → снимки новостей / отдельный Telegram
                         ↓ (сейчас обновление отдельной операторской процедурой)
Pipeline: merge → text/date gates → E5 chunks → тематический слой / ranking
                         ↓
Read-only catalog.sqlite + ranking.sqlite + npy/chunks
                         ↓
Python recommendation API → Next BFF /api/live → web
                         ↘
                         Runtime агента → разрешённый LLM-шлюз
                              ↑
                    факты компании + OCR/RAG банка
                              ↓
                    service.sqlite: runs/steps/calls/notes/reviews
```

Лента читает готовые векторы. Отдельного внешнего API нашей обученной модели нет.
Генерация — серверный вызов разрешённой LLM. Старт Docker не включает сборщики/дообучение. Отдельный pipeline.live worker
публикует версии, которые API подхватывает без рестарта.

### 4.3 Что важно знать о реализации

- Планирование детерминировано восемью группами правил; см. service/PLANNING.md.
  Узкое уточнение клиентских параметров пропускает первичный поиск банка с trace.
  Это собственный inspectable planner, а не обученная/free-form LLM-политика.
- Основной запрос получает primary news, до5 дополнительных публикаций той же
  candidate-story и банковские passages. Сходство не доказывает независимость
  первоисточников; автоматическое разрешение смысловых противоречий не готово.
- «Что произошло» сейчас — дословный lead первых двух предложений (до900символов).
  Это защита от смешивания события с интерпретацией, не полноценный extractor фактов.
- Банк-RAG — FTS/prefix + E5 semantic-event канал, RRF, даты до as_of, окно180дней,
  ограничение разнообразия и отсечение плотного OCR таблиц. Энкодеры news/bank и
  text/PDF SHA проверяются; независимый benchmark применимости ещё предстоит.
  Окно180дней — инженерная политика, не числовое требование ТЗ.
- Exact-quote/schema/ID проверки и отдельный LLM verifier не доказывают entailment
  каждого предложения. На отладке встречались ошибочные цитаты, отказы и чрезмерные
  требования к наличию имени клиента в новости; исправления не заменяют независимую оценку.
- Последние фиксы: граница слова для «ставка» (не «отставка»), dynamic30day cutoff,
  инвалидизация delivery при смене профиля/версии; сохранение вопроса и parent;
  диагностический trace для ошибок, bounded repair и сохранение клиентских вопросов
  вместо технических замечаний verifier в missing_context.
- `complete` — статус исполнения. `needs_context` — бизнес-статус недостаточных
  данных; он совместим с полезными условными выводами и конкретными вопросами.

### 5.3 Семантические ограничения исходников

- Единицы REVENUE_COMPANY не подтверждены. Нельзя объявлять значения рублями,
  тысячами рублей или автоматически относить все профили к сегменту >15млрд.
- Для доли рынка нет рыночного знаменателя. Доля наблюдаемых платежей — другая величина.
- Флаг кредита не раскрывает сумму долга, плавающую ставку и текущие условия.
  Флаг ФТС/список стран не подтверждают валюту и содержание действующего контракта.
- Совпадение GROUP_ID не доказывает собственность, гарантии или передачу риска.
- Заметка пользователя — candidate/user declaration, не банковская верификация.
- Связь по отрасли не означает подтверждённую узкую специализацию/конкретное событие.
- OCR чисел/таблиц нужно проверять по PDF. Стальной обзор2021года не текущий прогноз.
  Gold-обзор с неподтверждённой точной датой сейчас исключён из генеративного payload.
