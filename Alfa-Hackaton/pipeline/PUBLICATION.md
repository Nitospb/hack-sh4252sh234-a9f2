# Согласованные версии online-каталога

Это согласованная публикация W01.5. Непрерывный сбор подключён отдельным
[LIVE](LIVE.md); проверенная конфигурация — РБК/Интерфакс. Ни одна команда
ниже не запускает Chrome, старую history-очередь, Telegram или обучение.

Из корня приложения, Python с numpy:

```bash
python -m pipeline.publication --candidate /absolute/staging-catalog --root /absolute/releases
ALFA_CATALOG_RELEASES=/absolute/releases python recommendations/server.py --catalog pipeline/output/catalog.sqlite --state /absolute/state/feedback.sqlite
```

Кандидат должен быть заранее построен в отдельной папке командой `pipeline/build.py
--output ...`, затем `pipeline/ranked_catalog.py --catalog ... --output ...`.
Нельзя пересобирать файлы активной generation. Publisher копирует фиксированный
набор файлов, проверяет SQLite, связь ranking/catalog по SHA, все chunk/hash,
размерность/конечность векторов и одинаковый энкодер; сохраняет SHA каждого файла.
Синтетические данные допускаются только явным `--allow-synthetic` для smoke.

Версия — SHA манифеста файлов. `current.json` заменяется атомарно после fsync;
параллельный publisher исключён flock. Следующая версия не может молча удалить
существующие article_id/source_record_id; pruning требует отдельного migration-процесса. Повтор той же версии не создаёт ещё одну
папку. API проверяет манифест и загружает новые векторы перед переключением.
Каждый HTTP-запрос закреплён за одной generation; выполняющийся запрос сохраняет
предыдущую. При сбое остаётся последняя рабочая версия, ошибка видна в
`health.catalog_publication`. Повтор повреждённого указателя не вызывает тяжёлую
загрузку на каждом запросе: для исправления публикуйте новый указатель/версию.
Feedback, jobs, заметки и bank assets не копируются и не затираются.

Для Docker каталог releases должен быть смонтирован read-only **целиком**,
например `/catalog/releases`, и ALFA_CATALOG_RELEASES выставлен в тот же путь
внутри API-контейнера. Монтирование только current.json не позволяет видеть его
атомарные замены. В текущем Compose ALFA_CATALOG_RELEASES уже задана на /catalog/releases.
При наличии current.json API переключается на проверенное поколение в следующем
запросе; запуск worker остаётся отдельной командой.

Очистка: live-worker сохраняет три последние версии; прочие удаляются только
после проверки reader-leases и установки .deleting. Каждый активный Feed держит FileLease,
включая старый запрос после переключения. После эксклюзивного service-lock API
очищает свои аренды от прежнего аварийного запуска. Внешние прямые читатели обязаны
следовать тому же протоколу. Проверка/загрузка новой версии может задержать первый запрос;
на переключении в памяти временно находятся два набора mean-векторов. На диске
нужен запас под одну копию serving bundle. Здоровая текущая база не изменяется.
Планировщик, incremental staging и source health реализованы в pipeline.live.
Масштабирование на все источники и внешний сервер отдельно не принято.
