# Добавление и сопровождение источников

[Для агентов](../AGENTS.md) · [Архитектура](ARCHITECTURE.md) · [Контракт данных](DATA_CONTRACT.md)

## Конфигурация

Файл `config/sources.json` — рабочий каталог, `config/source-candidates.json` — отдельный каталог выключенных кандидатов. Каждый файл — объект с массивом sources. Каждый элемент передаётся в dataclass Source. Не добавляй произвольные поля без изменения модели. enabled управляет обычным запуском; явный `--sources <id>` выбирает адаптер даже при enabled=false.

Минимальный синтетический пример полного конфигурационного файла:

```json
{
  "sources": [
    {
      "id": "example_finance",
      "name": "Example Finance",
      "seeds": ["https://news.example/economy/"],
      "domains": ["news.example"],
      "article_pattern": "^/economy/[0-9]{4}/[0-9]{2}/[0-9]{2}/[^/]+/?$",
      "language": "ru",
      "publisher_country": "RU",
      "topics": ["finance", "economy", "business"],
      "body_selectors": ["//*[@itemprop='articleBody']//p"],
      "collection_priority": 100,
      "max_articles_per_cycle": 30,
      "enabled": false
    }
  ]
}
```

news.example — пример, не работающий новостной адаптер. Для реального сайта исследуй фактические ссылки и разметку, а затем замени значения.

## Все поля Source

| Поле | По умолчанию | Назначение/проверки |
|---|---|---|
| `id` | обязательное | уникальный slug `[a-z0-9_-]+`; используется также в пути профиля |
| `name` | обязательное | отображаемое имя |
| `seeds` | обязательное | стартовые URL разделов на разрешённых хостах |
| `domains` | обязательное | точные hostname без схемы; wildcard и автоматическое включение поддоменов отсутствуют |
| `article_pattern` | обязательное | regex только для path; используется re.search, поэтому обычно нужны якоря |
| `language` | обязательное | язык при отсутствии html lang |
| `publisher_country` | обязательное | страна издателя |
| `title_selectors` | [] | XPath заголовка при неоднозначных h1; принимает элементы или строки, первый непустой результат |
| `body_selectors` | [] | XPath элементов основного текста; первый достаточный результат имеет приоритет |
| `poll_seconds` | 300 | интервал обнаружения ссылок, минимум 60 |
| `min_interval_seconds` | 6 | минимум между навигациями, минимум допустимого значения 1 |
| `min_text_chars` | 180 | минимальная длина извлечённого основного текста |
| `enabled` | true | включён ли адаптер в обычный запуск |
| `topics` | [] | тематический профиль источника; записывается в source_topics |
| `max_age_days` | 14 | окно свежести сетевого сбора, минимум 1 |
| `listing_scrolls` | 0 | число скроллов страницы раздела, 0–3 |
| `listing_pages` | 1 | максимум страниц на seed, 1–5, включая стартовую |
| `notes` | пустая строка | необязательное описание адаптера; не сохранять здесь исторические логи и собранные статьи |
| `article_query_pattern` | null | дополнительный regex query; нужен для статей вида ?id=... |
| `source_kind` | news_media | тип источника, например company_blog/community/regulator |
| `collection_priority` | 50 | порядок отправки задач, 0–100 |
| `max_articles_per_cycle` | 20 | бюджет попыток источника, 1–1000; дополнительно ограничен CLI |
| `listing_link_selectors` | [] | XPath ссылок/атрибутов href только из нужной части раздела |

load_sources валидирует ID, совпадения хостов выбранных адаптеров, regex, часть лимитов и область seeds. Это не полная JSON Schema: корректность XPath и реальной разметки подтверждается отдельно.

## Правила областей URL

Один hostname должен обслуживаться одним Source, чтобы не разделять cookies и интервалы между несколькими адаптерами. Если нужны несколько рубрик одного издания, добавляй seeds в существующий Source. Финансовая и политическая рубрики одного домена не являются двумя источниками. www и голый домен являются разными hostname: включай оба только если сайт действительно использует оба. При локализованных или новых адресах учитывай фактический redirect/canonical, а не расширяй regex до любого пути.

article_pattern применяется к path, а query проверяется отдельно article_query_pattern. Например, путь `/press/event/` сам по себе не отличает статью от раздела; требование `(?:^|&)id=[0-9]+(?:&|$)` делает query частью области статьи.

Нормализация статьи удаляет fragment, utm_*, gclid/fbclid/yclid и сортирует остальные query-пары. Значимые параметры остаются. Для изображений применяется другой helper с сохранением подписанных параметров.

## Как работает discovery

Без listing_link_selectors просматриваются все a[href], включая боковые блоки. Для финансовых адаптеров это может приносить нерелевантные ссылки; предпочтительнее ограничить ссылки контейнером основной ленты.

Если listing_link_selectors заданы и ничего не нашли, отката ко всем ссылкам нет. Если XPath возвращает элементы a, для ранжирования доступен текст ссылки; если возвращает строки @href — только URL. Относительные ссылки разрешаются по первому base[href], как в браузере; внешние адреса всё равно проходят проверку области Source. Кандидаты сначала фильтруются по Source.accepts, дедуплицируются и ранжируются, затем применяется max-links.

У источников с приоритетом от 65 ранжирование отдаёт больший вес finance/economy, затем business/energy. Если politics входит в source.topics, политические ссылки получают такой же вес, как финансовые и экономические. Это словарная эвристика. Страницы сложной структуры всё равно требуют точного селектора и проверки содержимого.

Пагинация распознаёт явный rel=next и поддерживаемые aria-label, а не угадывает номера страниц. Следующая страница должна быть внутри пути исходного раздела и не являться статьёй. listing_scrolls даёт ограниченный скролл, а не универсальное нажатие «Загрузить ещё». `--max-links` действует на каждую страницу раздела, не на источник целиком.

## Выбор текста

Заголовок: title_selectors → JSON-LD headline → непустой h1 → og:title → title документа. Настроенный заголовок помогает отличать заголовок статьи от заголовка боковой колонки. Наличие title само по себе не отменяет проверку признаков статьи.

Порядок: body_selectors → разрешённый JSON-LD articleBody → Trafilatura. XPath тела должен возвращать элементы, не текстовые строки. При чтении контейнера удаляются script/style/noscript и сохраняются границы абзацев; это не заменяет точный селектор основного текста. Слишком широкий XPath может включить навигацию и рекомендации, а слишком узкий — потерять списки, подзаголовки или значимые части текста.

canonical на собственном домене, но вне области статьи, отклоняется. Canonical на другом домене не принимается как идентичность публикации; запись использует допустимый адрес и флаг. Сохраняется проверка признаков статьи: schema/дата/article с заголовком/og:type/настроенный контейнер тела.

Для платной статьи не обещай доступ к полному тексту. Фрагмент с полезным текстом можно сохранить с соответствующим text_scope; предложение купить подписку вместо текста не является новостью.

## Работа с изображениями

Специального поля image_selectors в Source сейчас нет. Общий candidates извлекает lead из метаданных и body из article и контейнеров, связанных с body_selectors. Поэтому изменение body_selectors может повлиять не только на текст, но и на изображения.

Проверь отдельно: основное фото; lazy-load/srcset; отсутствие аватара автора, рекомендаций и рекламы; связь article_id; соблюдение порога площади. Не ослабляй фильтры всей коллекции ради одного нестандартного сайта без проверки остальных сценариев. Отсутствие фото никогда не повод отклонять текст новости.

## Практический процесс

1. Выбери финансовый/экономический раздел и несколько реальных статей разных типов, включая короткую новость, длинный материал, фото/без фото, платный текст при наличии.
2. Уточни redirect, canonical, hostname, пути и дату. Не используй только один удачный URL как подтверждение работы всего сайта.
3. Добавь или уточни конфигурацию. Новый непроверенный адаптер добавляй в config/source-candidates.json с enabled=false и проверяй с --config config/source-candidates.json. После двух разных извлечённых статей и проверки основного текста переноси его в рабочий каталог, удаляя из кандидатов. ID и hostname должны оставаться уникальными между обоими файлами.
4. Добавь синтетический тест конкретной причины изменения: ложная ссылка на раздел, новая вложенная рубрика, дата в itemprop, тело в li и т.п. Не включай полный скачанный HTML сайта в Git.
5. Загрузи конфигурацию офлайн и выполни подходящие unit-проверки.
6. Сделай ограниченную живую проверку `check-sources` в отдельном runtime, минимум по двум различным каноническим статьям. Команды приведены в [эксплуатации](OPERATIONS.md).
7. Проверь не только код завершения: текст, canonical, дата, scope, сырой DOM, изображения и причины пропусков. Включай адаптер только после успешной проверки основного текста; недоступные сайты оставляй кандидатами или заменяй.
8. Сообщи, сколько статей реально проверено и какие типы ещё не проверялись. Не сохраняй результаты конкретного запуска в каталоге исходников.

Если сайт отдаёт 403/429/проверку доступа, проверь диагноз и паузу. Замена regex не устраняет сетевую блокировку. Если правила запрещают выбранный раздел, не расширяй обход в надежде скрыть эту причину. Изменения доступа и новые способы подключения должны следовать текущей задаче пользователя.
