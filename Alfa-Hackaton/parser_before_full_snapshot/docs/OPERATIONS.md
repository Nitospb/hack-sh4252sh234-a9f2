# Запуск, проверка и диагностика

[Для агентов](../AGENTS.md) · [Архитектура](ARCHITECTURE.md) · [Данные](DATA_CONTRACT.md) · [Источники](SOURCES.md)

## Окружение

Требуются Python 3.11+ и установленный Chrome/Chromium. Рабочий каталог команд ниже — `parser/`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m news_collector --help
```

Сборщик использует Selenium Manager при отсутствии явного ChromeDriver. `CHROME_BINARY` и `CHROMEDRIVER` либо одноимённые CLI-параметры позволяют задать исполняемые файлы. Для менеджера драйвера может понадобиться интернет даже при локальной проверке doctor.

На Linux код ищет google-chrome/google-chrome-stable/chromium/chromium-browser; зависимости установленного браузера предоставляет окружение. Автоматически подготовленного контейнера, systemd unit или серверного окружения в репозитории нет. Установку Windows нельзя считать поддержанной только по Windows UA: в коде используются fcntl и поиск исполняемых файлов macOS/Linux.

Не используй личный профиль Chrome. Профили создаются самим сборщиком под runtime.

## Параметры и команды

Глобальные параметры ставятся **до** имени команды:

| Параметр | Default | Назначение |
|---|---|---|
| `--runtime` | runtime | каталог БД, файлов и профилей, затем приводится к абсолютному пути |
| `--config` | config/sources.json | конфигурация; путь зависит от рабочего каталога |
| `--headless` | выключен | Chrome без окна |
| `--chrome-binary` | CHROME_BINARY или поиск | путь к браузеру |
| `--chromedriver` | CHROMEDRIVER или Selenium Manager | путь к драйверу |

| Команда | Назначение и основные параметры |
|---|---|
| `sources` | вывести id/name/enabled из конфигурации; браузер и runtime не нужны |
| `doctor` | реальный Chrome, локальный HTTP-сервер, HTTP/JS идентичность и переход по ссылке |
| `check-sources` | все ID конфигурации, включая enabled=false; --sources; --workers 1–4 (2); --max-articles 1–5 (2); --max-links (80); --resume |
| `collect` | один проход; --sources, --workers 1–4 (default 2), --max-articles (default 30), --max-links (default 300) |
| `run` | повторять collect-подобные циклы с ожиданием 30 секунд между ними; те же параметры |
| `stats` | агрегаты БД и очередь |
| `report` | coverage.md/coverage.json; --output меняет путь Markdown, JSON получает соответствующее расширение |
| `export` | --output, --max-age-days, --topics, --full-text-only, --require-date |
| `images` | заполнить фото архива; --sources, --workers 1–4, --limit (default 0, без ограничения) |
| `reextract` | --source обязателен; повторить извлечение выбранного источника из сохранённого DOM |
| `audit` | повторно проверить активные записи и карантин всех настроенных источников |
| `retry` | --source обязателен; сбросить ошибочные задания и паузу; --include-done также перечитывает сохранённые статьи |

`--max-articles` ограничивает попытки, а не число успешных новых новостей. `--max-links` действует на страницу раздела. `images --limit` ограничивает статьи, требующие сетевой загрузки фото; уже доступные/без кандидатов могут обрабатываться офлайн без расходования этого счётчика.

## Быстрая проверка без новостных сайтов

Для кода:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m news_collector sources
```

Тесты используют временные каталоги, синтетические HTML и подмены браузера. Они не требуют доступа к новостным сайтам и не запускают реальный Chrome. Разбор конфигурации в sources сам по себе не валидирует все ограничения Source; каталог также проверяется в тестах с явным выбором всех ID.

Файлы тестов:

| Файл | Что защищает |
|---|---|
| test_collector.py | URL/метаданные, даты, платные фрагменты, очередь, аренды, повторы, версии, Unicode-экспорт, изоляцию источника |
| test_expanded.py | каталог и приоритеты, финансовые ссылки, пагинацию, query-статьи, миграцию, карантин, фильтры экспорта, ошибку одного раздела |
| test_browser_navigation.py | переход к статье при сломанном URL polyfill сайта, повторное чтение динамической ленты и поздняя проверка доступа |
| test_source_check.py | реальные пути проверки с подменённым браузером: отдельные статьи, canonical-дубликаты, robots, свежесть, остановка, checkpoint и resume |
| test_images.py | CDN URL, кандидаты без рекомендаций, реальные размеры/формат, маленькие фото, текст до фото, связи Store, audit и CDP stream/ошибки хоста |

Для изменений только текста документации достаточно сверки с реализацией и проверки ссылок/примеров. Не запускай массовый сбор ради проверки Markdown.

## Ограниченная живая проверка

Пример для изменения адаптера; это сетевой запуск, а не часть unit-suite:

```bash
smoke_dir="$(mktemp -d /tmp/alfa-parser-smoke.XXXXXX)"
.venv/bin/python -m news_collector --runtime "$smoke_dir" --headless collect --sources interfax --workers 1 --max-articles 2 --max-links 30
.venv/bin/python -m news_collector --runtime "$smoke_dir" report
```

Проверь вывод команды, canonical, заголовок, основной текст, даты, scope и image-статусы. Каталог остаётся для просмотра и удаляется после проверки как отдельный тестовый runtime. Не подменяй рабочую БД пользователя этим запуском и не копируй его новости/скриншоты в Git.

Для изменения браузерной идентификации используй doctor с отдельным runtime:

```bash
.venv/bin/python -m news_collector --runtime /tmp/alfa-parser-doctor --headless doctor
```

Doctor сохраняет локальные результаты в doctor/report.json, doctor/headless.json или doctor/headed.json и browser.png. Он проверяет заголовки, Client Hints, JS-платформу и версию, webdriver и обычный Referer. Успех не означает доступ ко всем издателям или полное скрытие особенностей ОС/IP.

## Старт и остановка рабочего сбора

```bash
.venv/bin/python -m news_collector --headless run --workers 2
```

SIGINT/SIGTERM выставляют общий stop event. Очередь сохраняется, ожидания интервалов прерываются. Уже выполняющийся браузерный/CDP-вызов может завершаться дольше; сигнал не является жёстким таймаутом каждого сетевого ресурса. Не создавай второй процесс того же runtime для ускорения остановки.

На старте возобновляются очередь и профили. Это не сервис, автоматически запускаемый системой. В отчёте агент должен различать «код готов к run», «один collect завершён» и «фоновый процесс реально работает».

## Как трактовать результат

collect может сохранить часть статей и вернуть код 1 из-за ошибки другого источника или раздела. Код 0 не доказывает, что все сайты работают: возможны skipped, пустая очередь и отдельные robots-пропуски. Проверяй JSON-результат и coverage.

images возвращает 1 при error уровня источника. failed_images и filtered сами по себе не делают код завершения ненулевым. audit/reextract могут вернуть 0 с непустым массивом rejected; неожиданная ошибка командного уровня возвращает 1. Doctor возвращает 1 при неуспешном наборе проверок.

Основные поля результата источника:

- discovered — новые URL, реально добавленные в очередь; не все найденные ссылки;
- attempted — арендованные задания;
- saved — успешные сохранения, включая повтор уже известной статьи;
- new — новые ID статей;
- stale/stale_links/out_of_scope — пропуски по возрасту/области;
- failed/blocked/robots_disallowed — различные причины неуспеха;
- seed_errors — проблемы отдельных страниц разделов;
- skipped — источник сейчас не обрабатывался по указанной причине.

Coverage опирается на articles, последние завершённые runs и source_state. Статусы: collected, partial, blocked, robots_disallowed, error, validation_failed, no_articles, untested. collected означает наличие успешных примеров, не полную валидацию сайта. Сайт с ранее собранными статьями может иметь последний статус blocked.

## Типовые неисправности

| Наблюдение | Что проверить |
|---|---|
| Chrome не найден | установку браузера, CHROME_BINARY, путь к исполняемому файлу |
| несовместимый/недоступный драйвер | фактическую версию Chrome, CHROMEDRIVER, доступ Selenium Manager к загрузке |
| runtime заблокирован | другой процесс с этим runtime; остановить его или использовать другой каталог, не удалять живой lock-файл |
| нет ссылок | корректность seed/redirect, robots, listing_link_selectors, article_pattern, путь после локализации |
| раздел 404 | текущий адрес раздела; остальные seeds могут продолжать работать |
| статья «вне allowlist» | фактический redirect/canonical, hostname и вложенную рубрику; не расширять область до всего сайта без проверки |
| мало текста | source XPath, списки li, позднюю загрузку DOM, платный фрагмент, страницу ошибки или подписки |
| дата null | published_at_raw и publication_date_status; не присваивать fetched_at вместо даты |
| 403/429/captcha | различать AccessBlocked и ошибку парсинга; проверить паузу и реальные ограничения доступа |
| картинки filtered | width/height, площадь и короткую сторону; сам текст должен оставаться в articles |
| картинки failed | error, CDN/DNS, формат фактических байтов, лимит размера; не удалять новость |
| все фото CDN ошибочны | сетевую доступность; некоторые ошибки хоста кешируются на время браузерной сессии |
| новости есть в БД, но ещё нет в JSONL | цикл ещё не завершён; текст фиксируется раньше завершающего экспорта |
| после audit финансовая подборка устарела | выполнить отдельный export с фильтрами ниже |

Сырой DOM находится по raw_html_path; диагностика ошибки — в diagnostics/. Эти файлы могут содержать реальные материалы сайта и состояние браузера. Их место — локальный runtime, не исходники и не отчёт в публичном репозитории.

## Перерасчёт без сети

После исправления извлечения выбранного источника:

```bash
.venv/bin/python -m news_collector reextract --source rbc
```

reextract сохраняет корректные записи, перечисляет rejected, но не отправляет их в карантин. audit проверяет также ранее помещённые в карантин записи и может восстановить их:

```bash
.venv/bin/python -m news_collector audit
.venv/bin/python -m news_collector export --output runtime/financial-news.jsonl --max-age-days 14 --topics finance economy
```

Ни одна из этих команд не ходит на сайт за новой версией текста. Обе используют уже сохранённый DOM, сохраняют fetched_at и пересчитывают метаданные/кандидаты изображений. Существующие пригодные файлы используются повторно. После изменения порога размеров старые маленькие картинки перестают быть saved; сами старые файлы автоматически не удаляются.

Для актуального текста с сайта применяется retry --include-done, затем collect. У всех этих операций есть реальные побочные изменения БД; это не dry-run.

## Повторы и обновления

```bash
.venv/bin/python -m news_collector retry --source rbc
.venv/bin/python -m news_collector --headless collect --sources rbc --max-articles 3
```

retry сбрасывает failed/blocked/retry, attempts и last_error, а также паузу источника. Он не сбрасывает next_discovery, не возвращает skipped и не перечитывает done без --include-done. Не повторять бесконечно заблокированный сайт, не устранив причину.

Для повторной проверки уже сохранённых статей:

```bash
.venv/bin/python -m news_collector retry --source rbc --include-done
.venv/bin/python -m news_collector --headless collect --sources rbc --max-articles 3
```

С тем же canonical не создаётся новая статья; изменённый заголовок/текст создаёт новую пару article_id/content_hash в revisions.

## Заполнение фото архива

```bash
.venv/bin/python -m news_collector --headless images --sources rbc --workers 1 --limit 3
```

Кандидаты берутся из сохранённого DOM. Для каждого источника открывается один контекст статьи с проверкой robots; остальные картинки пакета загружаются через Chrome в этом контексте. Полный текст статей не перечитывается и fetched_at не меняется. Некоторые CDN могут зависеть от конкретного контекста/доступа, поэтому по URL из DOM не гарантируется успешный файл.

`images` не служит восстановлением утерянного сырого DOM. Для подготовки нужен raw_html_path. Сохранённые пригодные файлы переиспользуются; failed можно повторить, filtered не загружается заново, пока кандидат считается уже отфильтрованным. Пауза источника может привести к skipped и оставить pending.

## Экспорт, перенос и очистка

```bash
.venv/bin/python -m news_collector export --output runtime/finance.jsonl --max-age-days 14 --topics finance economy --require-date
```

Для стабильного бэкапа останови сбор и скопируй runtime целиком: БД, возможные WAL/SHM, raw, images и нужные профили. Один JSONL не восстанавливает очередь и историю. Перенос cookies/профилей между ОС не гарантирован. За пределами runtime требуется также конфигурация соответствующей версии кода.

Размер данных растёт: gzip DOM, фото, профили и диагностика не имеют автоматического retention. Проект не содержит планировщика очистки или команды безопасного удаления неиспользуемых файлов. Перед целевой очисткой учитывай articles, revisions, карантин и manifest, а не только наличие файла в одном JSONL. Чистка рабочего корпуса должна соответствовать задаче пользователя; тесты не требуют такой чистки.

Не запускай два export в один и тот же целевой файл параллельно: текущая реализация использует фиксированный суффикс .tmp. Аналогично для согласованного ручного отчёта лучше дождаться завершения цикла.

## Перед передачей работы следующему агенту

Укажи изменённые модули/адаптеры, выполненные проверки, число и типы реально проверенных страниц при сетевом запуске, оставшиеся ограничения и наличие работающего процесса. Не включай новости, скриншоты, cookies или старую переписку в документацию. Для фактических чисел текущего каталога читай sources.json; для доступности сайтов нужны свежие результаты runtime.

## Массовая проверка каталога

```bash
.venv/bin/python -m news_collector --runtime runtime/adapter-check --headless check-sources --workers 4 --max-articles 2
# Продолжение после остановки или изменения конфигурации
.venv/bin/python -m news_collector --runtime runtime/adapter-check --headless check-sources --workers 4 --resume
# Повтор конкретных исправленных адаптеров, в том числе после изменения кода
.venv/bin/python -m news_collector --runtime runtime/adapter-check --headless check-sources --sources interfax rbc --max-articles 2
```

Результаты: source-checks.json (checkpoint и метрики), source-checks.md (таблица), source-checks/<id>/samples.jsonl (полный извлечённый текст), article-*.html.gz и listing-*.html.gz (DOM). Это локальные проверочные данные: не коммитьте их. Картинки остаются кандидатами, их загрузка этой командой не проверяется. Проверка не обходит архив и не присваивает текущую дату материалам без даты.

На источник допускается до трёх попыток на каждую требуемую статью. Два разных URL с одинаковым canonical или одинаковым извлечённым текстом не подтверждают две отдельные статьи. Код 0 означает, что все выбранные источники получили статус passed и нужное число примеров; partial тоже даёт код 1. Сводный отчёт сохраняет и ранее проверенные ID, поэтому при целевом запуске счётчики отчёта относятся ко всему checkpoint, а код завершения — к выбранным ID.

После исправления движка повторяйте затронутые источники без --resume: fingerprint учитывает настройки Source, а не исходный код. Не включайте адаптер только по числу ссылок: просмотрите основной текст, качество, canonical и признаки платного фрагмента в samples.jsonl.

Рабочий каталог и кандидаты проверяются отдельно. Для кандидатов добавляйте глобальный параметр `--config config/source-candidates.json`. Не суммируйте строки двух каталогов как число работающих источников: рабочим считается только проверенный и включённый адаптер.
