# Проверяемые сценарии

В блоке разбора появился «Сравнить сценарии». Ключ LLM не нужен. Все параметры
вводятся явно; требуется подтверждение показанных допущений. Значения из CSV,
новости, ставки/курсы из модели не подставляются. Неизвестные единицы выручки не
используются. Результат не подтверждает фактический договор и не прогнозирует рынок.

POST /scenario принимает обычный company/source_record/user scope и parameters:

- kind=loan: currency, principal, days (целые1..3660), basis (360/365), rate_type.
  fixed: fixed_rate. floating: benchmark_base, benchmark_scenario, spread.
  Простые проценты: principal × annual_rate/100 × days/basis, остаток постоянен.
  Для fixed обе ставки одинаковы, изменение процентных расходов равно0.
- kind=fx: currency (USD/EUR/CNY), amount, rate_base, rate_scenario, flow
  (revenue/expense). Курсы — RUB за единицу валюты. Положительный cash_effect_delta
  означает улучшение денежного результата; для расходов рост курса даёт минус.
- acknowledge_assumptions=true обязателен. NaN/Infinity/булевы/неверные диапазоны
  отвергаются; Decimal, округление до0.01 только при выводе.

Ответ содержит нормализованные inputs, formula, assumptions и оба сценария.
Комиссии/налоги/капитализация/график погашений/хеджирование не рассчитываются.
История хранится в service.sqlite.scenarios, scoped по компании/строке/пользователю.
GET /scenarios возвращает20 последних; лимит хранения100 на профиль, без удаления
истории пользователем при новом расчёте. В текущем UI показаны3 последних.
Это отдельный инструмент: его числа не становятся автоматически доказательством
в LLM-разборе. Интеграция более сложных договорных формул остаётся отдельной задачей.

Тесты: test_scenarios.py и HTTP-тест; подмена user/record не открывает историю.
