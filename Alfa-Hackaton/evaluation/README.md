# Независимая оценка сервиса (W02, частичная реализация)

Контур не обучает модель, не вызывает LLM и не объявляет отзывы эталоном.
Пока утверждённой ручной разметки нет, измеренная точность продукта неизвестна.

## Рубрика v1 для экспертного согласования

Для пары конкретной новости с исходным профилем компании, ролью и датой:

- relevance 0: нет применимости или ложная экспозиция; 1: только общий контекст;
  2: полезная условная применимость с конкретным основанием; 3: приоритетное
  событие с существенной подтверждаемой экспозицией. Релевантность для P@k: >=2.
- exposure_correct: экспозиция следует из исходного факта, а не из одного ОКВЭД.
- claims_supported: существенные тезисы поддержаны первоисточниками по смыслу.
- numbers_correct: числа, единицы, периоды и вычисления сверены; null если чисел нет.
- bank_ai_separated: банковская позиция явно отделена от AI-переноса на клиента.
- action_useful: действие конкретно, выполнимо и не основано на выдуманном договоре.
- abstention_appropriate: отказ/уточнение соответствует реальному недостатку фактов.

Булевы поля допускают null = не оценено/не применимо. Каждая оценка должна
иметь reviewer и evidence (путь/страница/цитата/обоснование). Предпочтительно два
независимых оценщика, затем adjudicator для разногласий. Только status=adjudicated,
origin=human участвуют в метриках. Само указание этих полей не доказывает ручную
проверку: команда отвечает за реальность и журнал происхождения разметки.
Показывайте оценщикам замороженный контекст и оригиналы, скрывая имя системы.

## Формат входа и запуск

JSON-объект: dataset_version, catalog_version, rubric_version, split
(validation/test), queries. Формат query и judgments показан в
`test_score.py` на **синтетических** оценках; они не являются разметкой продукта.
Query хранит query_id/company_id/source_record_id/role/event_group/published_at,
rankings={system_name:[article_id,...]} и judgments=[...]. Сохраняйте исходный
run/trace рядом с набором; поле evidence ссылается на него и первичные данные.
Разные системы оцениваются на одинаковых запросах и объединённом пуле кандидатов.

```bash
python -m evaluation.score --input /absolute/frozen-evaluation.json --output /absolute/results.json --k 10
python -m unittest evaluation.test_score -v
```

Отчёт воспроизводим, содержит SHA входа и версии. P@k/nDCG вычисляются для
запросов с полностью оценённой выдачей; неизвестное не приравнивается к отрицательной
оценке. Для неполной разметки выводятся coverage и нижняя/верхняя границы P@k.
Короткая выдача штрафуется пустыми слотами в P@k. nDCG использует идеальную
сортировку **размеченного пула**, не всего корпуса; глобальный recall не заявляется.
Интервал bootstrap пересэмплирует запросы, seed фиксирован; при одном запросе null.
Измерения булевых критериев усредняются сначала по запросу, затем по запросам.

Для независимой выборки группируйте перепечатки/обновления в event_group до
разбиения по времени. В test не должно быть событий из train/validation; включите
сходные отрасли с разными экспозициями, нерелевантные новости, неоднозначные
валюты/единицы, старые PDF и случаи needs_context. Не подбирайте промпт/пороги по test.
Baseline: лексический/отраслевой поиск, исходный E5 и текущая персонализация.
Этот модуль считает сохранённые rankings; сбор baseline, экспертный
интерфейс/очередь и подключение результатов к quality пока не реализованы.
Рубрика подготовлена, но не согласована экспертами; W02 целиком не закрыт.


## Разбиение и аудит утечек

`evaluation.split` принимает JSON-массив article_id/event_group/published_at.
Группа, пересекающая временную границу, целиком исключается, а не распределяется
по разным split. Функция audit дополнительно проверяет готовые назначения по
article_id и event_group. Это не заменяет независимую проверку самих story groups.

```bash
python -m evaluation.split --input /absolute/grouped-news.json --output /absolute/partitions.json --validation-start 2026-10-10T00:00:00Z --test-start 2026-10-20T00:00:00Z
```

Даты выше — пример команды, не выбранные по качеству пороги. Сохраняйте manifest
рядом с frozen evaluation и проверяйте его до формирования экспертного пула.
