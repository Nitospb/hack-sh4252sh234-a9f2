# ОКВЭД → исходные 10 000 бизнес-тем → компании

Это сопоставление с первоначальным словарём `output/business_topics.jsonl`. Используются только его существующие ID `bt_`; новые темы и ID `ci_` здесь не создаются.

## Работа субагентов

Три субагента прочитали наблюдаемые точные коды и названия деятельности и выбрали подходящие объекты исходного справочника: 158 кодов производства и ресурсов, 291 код торговли/транспорта/финансов/ИТ, 97 кодов услуг. Итоговые JSON содержат явные выборы для каждого из 546 кодов; генераторы сохраняют предметные правила и уточнения подкодов. Сервисные и производственные сопоставления проверены друг другом, торговые — сервисным субагентом; замечания исправлены.

Субагенты сопоставляли виды деятельности, а не делали отдельный LLM-вызов на каждую компанию. Скрипт применяет готовое сопоставление ко всем 85 525 исходным записям (85 514 уникальных ID).

## Одному коду соответствует много тем

Выбирается конкретный объект в существующем разделе, затем подходящие его темы-события. Например, `01.11` охватывает зерновые, зернобобовые и масличные, кроме риса. Ему выбраны темы пшеницы, ячменя и других подходящих культур; рис исключён. Отдельно даны косвенные темы удобрений. Компания не объявляется производителем всех перечисленных культур: ассортимент неизвестен.

`49.41` получает темы видов грузовых автоперевозок как возможных специализаций и некоторые темы дизельного топлива как ресурса. Выпуск топлива компанией не предполагается.

Каждая связь содержит код, точное название деятельности, существующий `topic_id`, название темы, выбранный объект, тип соответствия и объяснение. Сигнал в теме («рост цен», «дефицит» и т.п.) означает информационный интерес, а не произошедшее событие у компании.

## Три типа соответствия

- `declared_activity`: объект непосредственно поддержан формулировкой заявленной деятельности. Это не независимая проверка фактических операций компании.
- `activity_scope_candidate`: объект может входить в широкую область деятельности, но специализация, ассортимент или способ работы не подтверждены. Такие связи нельзя показывать как доказательство конкретного продукта компании.
- `operating_exposure`: тема может влиять на работу компании как ресурс, технология или управленческий вопрос. Собственная деятельность в этой сфере не утверждается.

У широких и остаточных кодов сохраняется неопределённость. Отсутствующий объект не заменяется похожим из другой отрасли. Пробелы и частичное покрытие перечислены в `gaps.json`; часть кодов имеет только косвенные интересы, часть не имеет подходящих тем.

## Поиск компаний по темам

Из `Alfa-Hackaton`:

```bash
python3 taxonomy/map_okved_to_topics.py search пшеница --mode activity --limit 20
python3 taxonomy/map_okved_to_topics.py search логистика --mode activity --limit 20
python3 taxonomy/map_okved_to_topics.py search ИИ --mode interest --limit 20
python3 taxonomy/map_okved_to_topics.py company U_67 --limit 10000
```

Режимы:

- `declared` — только непосредственно поддержанное формулировкой кода;
- `activity` — также возможные специализации в пределах широкой деятельности;
- `interest` — дополнительно косвенные операционные интересы.

Запрос «ИИ» не должен означать «компания доказанно разрабатывает ИИ». Один ОКВЭД разработки ПО этого не доказывает. В текущем наборе ИИ встречается как косвенный интерес, например возможное применение моделей в ПО или диагностике. Результат показывает тип соответствия и его причину. Используются алиасы ИИ/AI/искусственный интеллект и логистика; для остальных запросов — поиск фразы по названиям и ключам исходных тем, без морфологии и внешнего семантического сервиса. Порядок результатов определяется количеством совпавших тем, а не доказанным бизнес-влиянием.

## Файлы и структура

`output/okved_topic_mapping/`:

- `okved_topic_links.csv` — развёрнутая таблица ОКВЭД ↔ тема с типом и объяснением; одному коду соответствует множество строк.
- `okved_topics.jsonl` — по одной записи на код: все ID тем, группы объектов, объяснения и пробелы покрытия.
- `company_topic_index.csv` и `.jsonl` — все исходные записи компаний с кодом и количеством тем; `mapping_key` ссылается на запись того же ОКВЭД в `okved_topics.jsonl`. Список тем хранится один раз на код, а не многократно для всех компаний.
- `okved_topics.sqlite` — готовый индекс для получения тем компании и поиска компаний по темам. Таблицы `topics`, `activities`, `bindings`, `mapping`, `companies`.
- `gaps.json` — отсутствие или неполнота подходящих тем исходного словаря.
- `validation.json` и `verify_report.json` — количественные проверки и хеши источников.
- `example_*.json` — примеры запросов и карточки компании с существующими ID тем.

Ручные решения субагентов: `okved_mapping/industry.json`, `trade.json`, `services.json`. Семантические замечания аудита хранятся в `output/okved_*_semantic_audit.json`; это история обнаруженных замечаний, последующие исправления находятся в итоговых сопоставлениях.

## Сборка

```bash
python3 taxonomy/map_okved_to_topics.py build --source ../data/dataset/df_Uid_data_hack.csv
python3 taxonomy/verify_okved_mapping.py --source ../data/dataset/df_Uid_data_hack.csv
python3 -m unittest discover -s taxonomy -v
```

Python 3.10+, стандартная библиотека. Исходный словарь из 10 000 тем не изменяется. Прошлые выгрузки `company-interests.v1` и обогащения по графу используют отдельные `ci_` темы; они сохранены как отдельные результаты и не смешаны с этим сопоставлением. Перенос графовых связей на новый `bt_` индекс — отдельный этап интеграции, здесь выполнено именно ОКВЭД-сопоставление и поиск по нему.

ОКВЭД здесь трактуется по предоставленным названиям и семантическим правилам, не как юридически заверенная классификация. Количественная проверка не заменяет отраслевую экспертизу.

## Итог проверки

Проверены все 546 наблюдаемых кодов. У 310 есть темы собственной области деятельности (включая кандидатов), ещё у 200 — только косвенные операционные интересы; для 36 подходящих тем не найдено. В сопоставлении использованы 6 712 существующих тем из 10 000, сформировано 18 810 записей связей. У кода может быть до 240 различных тем. Все 85 525 исходных записей компаний сохранены в индексе: 59 828 имеют темы области деятельности, 23 749 — только косвенные интересы, 1 948 — явный пробел словаря.

Независимая сверка подтвердила соответствие первоначальным ID, точным объектам/сигналам, кодам и всем исходным компаниям; CSV, JSONL и SQLite согласованы. 22 модульных теста прошли. Эти проверки не являются измерением семантической точности.
