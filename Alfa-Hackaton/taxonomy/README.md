# Общие бизнес-темы для компаний и новостей

**Сопоставление ОКВЭД с исходными 10 000 темами:** [таблица соответствий, поиск компаний и запуск](OKVED_MAPPING.md).

**Обогащение по платежам и связанным компаниям:** [метод, объяснения связей и выгрузки](RELATIONSHIP_INTERESTS.md).

**Назначения 10+ тем каждой компании:** [описание, выгрузки и запуск](COMPANY_INTERESTS.md). Это более новый результат по полному датасету; ниже описан исходный общий справочник и его кандидатная классификация.

Справочник нужен для отбора кандидатов в персональную ленту: компания → потенциальные бизнес-экспозиции → темы события → проверка влияния → инсайт. Это часть решения кейса, а не готовый сервис персонализированной аналитики.

## Что выяснено по проекту и заданию

- Задание требует объяснять последствия для конкретного бизнеса, учитывать аналитику банка, сохранять источники и выполнять многошаговую агентную проверку. Количество 10 000 — требование пользователя к этому справочнику, а не критерий из PDF.
- `frontend/src/data/demo.ts` содержит демонстрационные компании/события; схема `NewsEvent.per` хранит интерпретации по клиентам. Наличие экранов и архитектурной схемы не означает наличие работающего сервера персонализации.
- `parser/news_collector/topics.py` выделяет восемь широких категорий регулярными выражениями. Они полезны для сбора, но недостаточны для подробных интересов компаний. Этот модуль не изменён: новая бизнес-таксономия хранится отдельно от технических фильтров парсера.
- В исходных CSV: 85 525 компаний, 12 514 связей пользователей с компаниями, 1 380 585 платёжных связей (по `data/dataset_summary.json`). Доступны ОКВЭД, регион, выручка, группа, банковские продукты и ВЭД. Эти данные не доказывают ассортимент, валюту обязательств, долю рынка или конкретные поставки.
- Платёжный граф позволяет расширять релевантность через контрагентов, но направление платежа само по себе не доказывает цепочку поставок. В текущем модуле граф не используется.

## Устройство справочника

Три субагента подготовили авторские словари в `seeds/`: производство; торговля/услуги; финансы/IT/корпоративные функции и макроэкономика. Всего 100 разделов. Каждый содержит 10 объектов и 10 событий/аспектов. Раздел разворачивается в 100 сочетаний «объект: событие», итого ровно 10 000 тем.

Это композиционный стартовый словарь, не 10 000 вручную размеченных примеров и не официальная классификация. Уникальность строк не доказывает семантическую независимость. Применимость сочетаний, пересечения разделов и поисковые фразы требуют отраслевой экспертной проверки. Такой статус явно записан в `validation.json`.

Поля: `topic_id`, `name`, `sector_id`, `sector_name`, `object`, `signal`, `object_keywords`, `signal_keywords`, `okved_prefixes`, `company_conditions`, `taxonomy_version`, `status`.

ID получен из ID раздела и нормализованного названия; перестановка строк ID не меняет. Переименование создаёт новый ID: для промышленной эксплуатации нужны таблица миграций и история версий. Русские ключевые фразы — подсказки для поиска; их список не исчерпывает все формы и синонимы.

## Запуск

Только Python 3.10+, внешние зависимости и сеть не нужны. Из корня репозитория `Alfa-Hackaton`:

```bash
python3 taxonomy/taxonomy.py build
python3 -m unittest discover -s taxonomy -v
python3 taxonomy/taxonomy.py evaluate --companies ../data/dataset/df_Uid_data_hack.csv --articles parser/runtime/articles.jsonl
python3 taxonomy/taxonomy.py classify --input taxonomy/examples/article.json
python3 taxonomy/taxonomy.py profile --input taxonomy/examples/company.json
```

`build` проверяет количество, уникальность имён и ID, обязательные поля; выпускает JSONL, CSV UTF-8 BOM и отчёт. `evaluate` читает все компании и текущий локальный корпус новостей, выпускает `coverage.json`, `company_sector_candidates.jsonl` и `article_topic_candidates.jsonl`. Тексты/исходный корпус не перезаписываются. Повторный запуск перезаписывает производные файлы в `output/`.

## Как присваивать темы

1. Профиль компании получает **кандидатные разделы** по префиксам ОКВЭД и активным флагам продуктов. Флаги объединяются по «ИЛИ». Подсказки ОКВЭД приблизительные; сквозные функции без явных данных не присваиваются автоматически. Неизвестный ОКВЭД может дать пустой результат.
2. Новость получает **кандидатные темы**, когда найдены фраза объекта и фраза события на расстоянии до 240 символов. Границы слов защищают от совпадения «газ» в «магазин». Нет морфологии, переводов, отрицаний или проверки причинной связи. Отсутствие совпадений означает воздержание, а не отсутствие бизнес-значения.
3. Совместный список — темы новости, чей `sector_id` входит в кандидатные разделы компании. Он ещё не доказывает, что событие влияет на клиента. В `examples/match.py` есть запускаемый пример соединения.
4. Следующий агент проверяет фактическую деятельность, сущности, географию, даты, прямую/косвенную экспозицию и противоречия. После этого тема может получить статус подтверждённой и доказательства. Нужен отдельный статус `rejected` с причиной.
5. RAG подбирает материалы банка; интерпретация отдельно хранит факт, позицию банка, AI-вывод, допущения и источники. Нельзя объявлять суждение из словаря позицией банка.

`retrieval_score` — число совпавших поисковых фраз, не вероятность, оценка риска или финансовый эффект. По умолчанию сохранены первые 20 кандидатов на новость; `total_candidates` и `truncated` показывают усечение. Для полного вывода вызывайте `Matcher.classify(article, limit=10000)`.

## Что дальше для рабочего качества

Нужна размеченная выборка пар компания/новость: precision@k, recall@k, доля воздержаний, точность по редким отраслям, устойчивость к отрицаниям и нерелевантным совпадениям. Текущий отчёт измеряет только покрытие словаря. Затем можно добавить морфологию и embeddings для поиска кандидатов, reranker для проверки контекста, графовые экспозиции и обратную связь пользователя. Все этапы должны сохранять версию справочника и основания привязки.

## Проверка на локальном срезе

На момент прогона: 85 525 компаний, кандидатные разделы найдены для 69 270 (около 81%); 39 новостей, кандидатные темы найдены для 10. Это не измерение точности. Остальные новости требуют более полного словаря, морфологии/семантического поиска либо действительно находятся вне охваченных бизнес-тем. Сквозная макроэкспозиция клиентов отдельно не подтверждалась. Структурные проверки 10 000 имён/ID и четыре теста механизма привязки прошли. Полные машинные отчёты находятся в `output/`.
