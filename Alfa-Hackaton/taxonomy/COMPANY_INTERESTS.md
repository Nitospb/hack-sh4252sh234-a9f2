# Темы интереса для каждой компании

Пользовательская задача: пройти весь исходный датасет и присвоить каждой компании минимум 10 тем, связанных с её деятельностью. Этот модуль формирует **конкретный список тем на каждую исходную запись**, а не только кандидатные отраслевые разделы.

## Основания

Три субагента подготовили по 12 отраслевых аспектов для каждого двухзначного раздела ОКВЭД, встречающегося в датасете. Правила находятся в `company_rules/*_rules.json`. Для каждого точного кода и названия деятельности аспект получает свой контекст и устойчивый ID:

`Торговля оптовая компьютерами, периферийными устройствами к компьютерам и программным обеспечением — [отраслевой аспект]`.

Компания получает 12 таких тем по своим `MAINOKVED_CODE` и `MAINOKVED_NAME`. Не утверждается, что конкретная компания продаёт все возможные товары своего раздела или выполняет все возможные операции. Темы описывают потенциально значимые вопросы её заявленной деятельности.

Дополнительно каждый активный флаг `CL_PRODUCT_RKO_MARK`, `CL_PRODUCT_LOA_MARK`, `CL_PRODUCT_GAR_MARK`, `CL_PRODUCT_LEA_MARK`, `CL_PRODUCT_DEP_MARK`, `CL_PRODUCT_ZPP_MARK`, `FACTORING_MARK`, `FTS_FLAG` добавляет две связанные темы. Нулевые и пустые флаги ничего не добавляют. Поэтому у компаний одной деятельности списки могут различаться. Продуктовые темы сохраняют контекст основной деятельности и не вытесняют 12 отраслевых тем.

Преобразование выполняет воспроизводимый скрипт. Субагенты разрабатывали отраслевые правила; отдельного LLM-вызова на каждую компанию не было. Все исходные строки проходят обработку и последующую сверку. Никакой фильтрации по выручке или клиентскому сегменту нет.

Это отдельный каталог `company-interests.v1` с ID `ci_`. Он расширяет точность покрытия реальных видов деятельности и **не является автоматической привязкой к прежним 10 000 темам `bt_`**. Старый каталог сохранён. Для единого индекса новостей нужно индексировать новый каталог либо отдельно подтвердить соответствия между каталогами; совпадение двухзначного раздела не является таким подтверждением.

## Выходные файлы

Все файлы находятся в `output/company_interests/`:

- `company_interests.csv` — удобная выгрузка всех записей: ID компании, исходная строка, ОКВЭД, деятельность, регион, число тем, списки ID и названий. CSV UTF-8 BOM; списки внутри ячеек закодированы JSON.
- `company_interests.jsonl` — те же назначения, дополненные основаниями, методом и версией; одна запись на строку исходного CSV.
- `activity_interest_catalog.csv` и `.jsonl` — общий справочник назначенных тем; `rationale` объясняет связь аспекта с деятельностью, `required_flag` в JSONL указывает необходимый продуктовый признак.
- `company_interest_index.jsonl` — одна запись на уникальный ID компании со ссылками на её исходные профили.
- `company_interests_validation.json` — количественный отчёт, SHA-256 исходного файла, список конфликтов и результаты полноты.
- `company_interests_examples.json` — примеры разных отраслей для просмотра.

Темы являются **выведенными интересами по данным**, а не подтверждёнными пользователем предпочтениями или установленными финансовыми рисками. В справочнике есть связь с деятельностью; при отборе новости требуется учитывать одновременно аспект и точный отраслевой контекст. Совпадение слов «цены» или «регулирование» без контекста компании недостаточно.

## Конфликт в исходном датасете

В исходных данных один ID, `U_428697`, встречается 12 раз с разными ОКВЭД и регионами. Эти записи не объединяются автоматически. У каждой есть `source_record_id` вида `U_428697:line:85515`, собственные темы и статус `conflicting_company_records_review_required`. Индекс компании перечисляет все варианты. Нельзя считать объединение этих тем достоверным консолидированным профилем одной компании без исправления источника.

## Запуск и проверка

Из `Alfa-Hackaton`:

```bash
python3 taxonomy/assign_company_interests.py --source ../data/dataset/df_Uid_data_hack.csv
python3 taxonomy/assign_company_interests.py --source ../data/dataset/df_Uid_data_hack.csv --verify-only
python3 -m unittest discover -s taxonomy -v
```

Python 3.10+, стандартная библиотека, без сети и внешних моделей. Повторный запуск перезаписывает только производные файлы назначения.

Сверка проверяет каждый исходный ID и номер строки, код и название деятельности, минимум 10 разных ID тем, существование каждой темы в каталоге и её соответствие точному виду деятельности; для дополнительных тем — активность нужного флага. Также проверяются количество CSV-строк и полнота индекса уникальных компаний.

Количественная полнота не доказывает качество интересов. Отраслевые аспекты требуют экспертной проверки и обратной связи пользователей. Регион, платёжные связи и принадлежность к группе сохраняют значение для следующего этапа ранжирования, но не используются здесь для недоказанных выводов о поставщиках, валюте долга или конкретных товарах.

## Итог полного прогона

Обработано 85 525 исходных записей, 85 514 уникальных ID компаний, 546 точных видов деятельности в 76 разделах. Каждой записи присвоено от 12 до 26 различных тем; всего 1 229 802 назначения. В использованном каталоге 12 830 тем. Записей без тем или с числом тем меньше 10 нет. Все проверки полной выгрузки и восемь модульных тестов прошли. Для одного конфликтующего ID сохранены отдельные профили.
