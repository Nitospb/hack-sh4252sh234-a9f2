# Парсер финансовых и политических новостей

Python 3.11+, Selenium и Chrome/Chromium. Сборщик обнаруживает новые статьи на настроенных сайтах, извлекает текст и метаданные, сохраняет изображения и экспортирует данные для дальнейшей обработки. Российские финансовые источники имеют наибольший приоритет.

## Документация для разработки

Начните с [AGENTS.md](AGENTS.md): там собраны инварианты и порядок работы с кодом. Подробные руководства:

- [Архитектура и поток обработки](docs/ARCHITECTURE.md).
- [Контракт статей, изображений, SQLite и экспорта](docs/DATA_CONTRACT.md).
- [Добавление и сопровождение источников](docs/SOURCES.md).
- [Запуск, проверки, диагностика и обслуживание](docs/OPERATIONS.md).

## Установка

Установите Chrome/Chromium и выполните из корня репозитория:

```bash
cd parser
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
```

Selenium Manager подбирает ChromeDriver. Пути при необходимости задаются переменными `CHROME_BINARY` и `CHROMEDRIVER`. Для первоначальной загрузки драйвера нужен интернет.

## Запуск

Все команды выполняются из папки `parser`:

```bash
# Проверка Chrome и идентификации браузера на локальном HTTP-сервере
.venv/bin/python -m news_collector --headless doctor

# Проверить все адаптеры, включая выключенные (две статьи на источник)
.venv/bin/python -m news_collector --runtime runtime/adapter-check --headless check-sources --workers 4

# Ограниченный проход
.venv/bin/python -m news_collector --headless collect --sources interfax rbc --max-articles 3

# Постоянный сбор; остановка Ctrl+C
.venv/bin/python -m news_collector --headless run --workers 2

# Публикации за последние 30 дней, отдельный возобновляемый корпус
.venv/bin/python -m news_collector --runtime runtime/month --headless history --days 30 --workers 4 --target 12000 --defer-images

# Изображения можно скачать после наполнения текстового корпуса
.venv/bin/python -m news_collector --runtime runtime/month --headless images --workers 4

# Статистика, экспорт и отчёт доступности источников
.venv/bin/python -m news_collector stats
.venv/bin/python -m news_collector export
.venv/bin/python -m news_collector report
```

Глобальные параметры `--headless`, `--runtime` и `--config` ставятся перед командой. Без `--headless` Chrome запускается с окном. Одновременный запуск двух сборщиков в одном runtime запрещён файловой блокировкой.

## Источники и очередь

Подборки до 20 статей по объектам/отраслям пользовательского CSV, каталог профильных сайтов и отдельный поток публичных Telegram-каналов для внутренней аналитики описаны в [INTERESTS](docs/INTERESTS.md). Команда `interest-export` читает уже собранный корпус без остановки Chrome; команда `telegram` пишет в отдельную БД и не попадает в обучающие выгрузки.

`config/sources.json` содержит рабочий каталог. `config/source-candidates.json` хранит отдельно выключенные кандидаты; для них используйте явный `--config config/source-candidates.json` и свежую проверку перед переносом в рабочий каталог.

Конфигурация задаёт стартовые разделы, разрешённые домены и пути статей, язык, страну издателя, селекторы, частоту обхода и приоритет. Команда `sources` показывает список. При явном `--sources` можно проверить и выключенный адаптер.

Список сайтов конфигурируется заранее; ссылки на новости обнаруживаются автоматически. Извлечение использует правила сайта, JSON-LD и Trafilatura. Поддерживаются ограниченная пагинация и скролл. Добавление нового сайта требует проверки его разметки и доступа.

Очередь и версии статей хранятся в SQLite WAL. После остановки обработка продолжается с сохранённого состояния. Обычные ошибки повторяются с задержкой, блокировки доступа приостанавливают источник. Учитываются robots.txt и Crawl-delay. Ошибка одного источника не останавливает остальные.

Свежесть ограничивается настройкой `max_age_days`; неизвестная дата сохраняется с флагом. Темы finance, economy, politics, business, ai, technology и energy определяются словарными эвристиками и не заменяют семантическую классификацию. Платные доступные фрагменты отмечаются отдельно; полнота текста не гарантируется.

Идентификация Chrome под Windows задаётся автоматически с учётом реальной версии браузера. Профили разделены по источникам. Капчи, ограничения доступа и подписки автоматически не обходятся.

## Сбор за период

`history` обходит текущие разделы, явную пагинацию, настроенные архивные страницы и sitemap, включая вложенные индексы и gzip XML. Sitemap берётся из robots.txt или `sitemap_urls`; если адресов нет, проверяются `/sitemap.xml` и `/sitemap_index.xml`. Навигации и загрузка XML идут через Chrome с существующими интервалами, robots и паузами при ограничении доступа.

Для точного периода используйте `--since 2026-09-24 --until 2026-10-25`: начало включительно, конец исключительно, даты означают полночь UTC. ISO-время должно содержать часовой пояс. Вместо диапазона можно задать `--days 30`; по умолчанию также 30 дней. На первом запуске границы фиксируются в `history-job.json`. Повтор той же команды продолжает **тот же** интервал, а не сдвигает его относительно нового времени запуска. Для другого периода нужен другой runtime.

Сбор за период требует отдельный runtime, чтобы статусы очереди текущего мониторинга не подавляли архивные статьи. Обычный лимит свежести `max_age_days=14` в этом режиме не действует. Дата URL, sitemap `lastmod` и дата sitemap news используются для поиска/приоритета; принадлежность корпусу определяется датой публикации самой статьи. `lastmod` никогда не подменяет `published_at`.

Результаты находятся в выбранном runtime:

- `period-news.jsonl` — публикации с подтверждённой датой в заданном интервале, включая отмеченные платные фрагменты.
- `training-news.jsonl` — тот же период без известных платных фрагментов и точных дублей основного текста; именно это число сравнивается с `--target`.
- `undated-news.jsonl` — сохранённые тексты без подтверждённой даты; в цель не засчитываются.
- `history-report.json` и `history-report.md` — количество по дням и источникам, очереди, ошибки и достигнутые бюджеты.
- `news.sqlite3`, `raw/`, `sitemaps/`, `images/` — состояние, исходный DOM, XML и связанные фото.

`--target` по умолчанию 10 000. После достижения цели завершается текущий круг источников: каждый выбранный источник получает возможность обработки, поэтому итог может превышать цель. `--max-pages` (80) и `--max-articles` (500) — накопительные бюджеты на источник, а не гарантии успешных статей. Их можно увеличить при возобновлении. `--rounds N` ограничивает один запуск N кругами; 0 — до цели или исчерпания доступной очереди/бюджетов. Повтор того же целевого значения после его достижения сразу обновляет отчёт; для продолжения увеличьте цель.

При возобновлении первыми идут ещё не посещённые источники, затем те, которые дольше всего не получали проход. Частые остановки не должны каждый раз возвращать сбор только к первым сайтам каталога. У индексов с равным lastmod порядок зависит от издателя; `sitemap_reverse` позволяет начать с последних разделов проверенного индекса. Daily/latest sitemap получают дополнительный приоритет, но не заменяют месячный архив.

При изменении настроек адаптера fingerprint меняется: стартовые разделы и корневые sitemap перечитываются, уже сохранённые статьи остаются обработанными. При обновлении формата служебных таблиц добавляются недостающие поля без удаления очереди или корпуса.

По умолчанию изображения скачиваются после текста каждой статьи. `--defer-images` оставляет кандидаты со статусом pending для последующей команды `images`; отсутствие фото не исключает статью. После `images` повторите `history` с тем же интервалом/целью для обновления периодных JSONL.

Код выхода: 0 — цель достигнута, 2 — запуск завершён ниже цели (бюджет, ограниченные круги, недоступность или исчерпание), 130 — остановка сигналом, 1 — ошибка команды. Источники со статусом blocked/error повторно не открываются до явного `--retry-failed`; пауза доступа при этом сохраняется.

Это ограниченный обход доступного архива, а не гарантия всех публикаций каждого сайта. News sitemap часто содержит только последние двое суток; для глубины нужны обычные sitemap или архивные разделы. Закрытые статьи, отсутствующие архивы, нестандартные кнопки загрузки и неизвестные даты уменьшают покрытие. Текущий DOM старой статьи показывает её содержимое сейчас, а не историческую версию на дату публикации. Семантическая дедупликация, разметка рекомендаций и построение эмбеддингов не выполняются.

## Результаты

Результаты создаются локально в `runtime/` и исключены из Git:

```text
runtime/news.sqlite3          статьи, версии, очередь и связи с изображениями
runtime/articles.jsonl        весь корпус последних версий
runtime/financial-news.jsonl  подборка finance/economy за 14 дней
runtime/finance-politics-news.jsonl  подборка finance/economy/politics за 14 дней
runtime/images/<article_id>/ оригиналы изображений и manifest.json
runtime/raw/                 сжатый исходный DOM
runtime/coverage.md          отчёт по источникам
runtime/coverage.json        машиночитаемый отчёт
runtime/profiles/            ссылки на отдельный каталог состояния Chrome
runtime/diagnostics/         диагностика ошибок при работе
```

Все три JSONL и отчёт автоматически обновляются после завершения цикла. Данные, профили и диагностические файлы не входят в поставку кода.

## Хранение состояния Chrome и очистка

Физические профили и HTTP-кэш находятся отдельно от корпуса: macOS — `~/Library/Caches/alfa-news-collector/<runtime-id>/`, Linux — `${XDG_CACHE_HOME:-~/.cache}/alfa-news-collector/<runtime-id>/`. При необходимости корень задаётся `ALFA_BROWSER_CACHE`; его нельзя помещать внутрь runtime новостей. Каждый runtime имеет свой namespace, каждый источник — свой профиль; личный Chrome не используется.

`runtime/profiles/<source_id>` остаётся совместимой ссылкой на физический профиль. Старые закрытые профили переносятся с сохранением cookies, Local State, Preferences, Local Storage, IndexedDB и состояния service worker. При конфликте двух непустых профилей автоматическое объединение запрещено: оба сохраняются для проверки.

После закрытия браузера удаляются HTTP/JS/GPU-кэш, загрузочный кэш компонентов, служебные локальные модели/озвучивание и метрики из точного списка `profile_cache.DISPOSABLE`. Сертификаты и списки безопасности сохраняются. Chrome может повторно скачать часть компонентов во время следующего запуска; после закрытия они снова очищаются. HTTP-кэш вынесен в отдельную папку `http/<source_id>` и запрашивает размер 8 MiB. Этот параметр Chrome является рекомендацией для его кэша, а не строгой квотой всего профиля.

Для уже работающего сборщика старой версии можно включить обслуживание без его остановки:

```bash
# PID нужно взять у реального процесса history/run; команда работает отдельным процессом
.venv/bin/python -m news_collector.profile_cache --runtime runtime/month --watch-pid COLLECTOR_PID --interval 30 --grace-seconds 180
```

Обслуживание проверяет lease сборщика, процессы Chrome и SingletonLock. Активные и недавно закрытые профили пропускаются; в указанном примере выдерживается три минуты. Отчёт `maintenance.json` лежит в отдельном namespace кэша. Новости, SQLite, очередь, raw DOM, JSONL, изображения и ZIP-экспорты не очищаются. Проверка ownership и символьных ссылок не позволяет обходить каталог Chrome или удалять произвольные файлы.

Не удаляйте весь системный каталог кэша ради очистки: он содержит также cookies и настройки сайтов. Используйте описанное обслуживание, которое сохраняет это состояние. Выгрузка корпуса не должна включать браузерный namespace.

Статья содержит стабильный `id` (SHA-256 канонического URL), источник, URL, заголовок, текст, даты, авторов, темы, тип источника, признаки качества и `content_hash` версии текста. Даты с известным часовым поясом приводятся к UTC; неизвестные значения не подменяются временем скачивания.

Для пользовательского отбора:

```bash
.venv/bin/python -m news_collector export --output runtime/finance.jsonl --max-age-days 14 --topics finance economy --require-date
```

## Изображения

Текст записывается в базу **до** загрузки картинок. Отсутствие, фильтрация или ошибка изображения не исключают новость.

Сохраняются изображения с площадью от **160 000 пикселей** и короткой стороной от **200 пикселей**: 400×400 и 640×360 подходят. Картинки из рекомендаций, интерфейса и мелкие изображения отсекаются эвристиками. Максимум шесть сохранённых ссылок на статью, 10 MiB и 40 мегапикселей на файл. Pillow проверяет реальные размеры и формат JPEG/PNG/WebP/GIF/AVIF; байты оригинала не перекодируются.

Поле `main_image_path` указывает на основное фото относительно runtime. Массив `images` хранит `article_id`, исходный URL, локальный путь, размеры, формат, SHA-256 и статус saved/pending/filtered/failed. В папке каждой статьи есть `manifest.json` с её ID, заголовком и URL. В SQLite те же связи доступны в `article_images`.

Для заполнения изображений ранее собранных статей:

```bash
.venv/bin/python -m news_collector --headless images --workers 2
```

Загрузка идёт через Chrome, включая уже загруженные ответы и CDP Network.loadNetworkResource. Не гарантируется извлечение любой нестандартной галереи, CSS-background или canvas. При переносе корпуса копируйте runtime целиком.

## Обслуживание

```bash
# Повторное извлечение из сохранённого HTML без сети
.venv/bin/python -m news_collector reextract --source rbc

# Проверка всего корпуса; некорректные записи переходят в карантин
.venv/bin/python -m news_collector audit

# Повторная постановка неудачных статей после устранения причины
.venv/bin/python -m news_collector retry --source rbc

# Проверки на синтетических данных без новостных сайтов
.venv/bin/python -m unittest discover -s tests -v
```

`audit` сохраняет исходный DOM и историю; после исправления адаптера запись может быть восстановлена. Ссылки на имеющиеся изображения сохраняются при повторном извлечении. Файлы runtime не удаляются автоматически.

## Проверка работоспособности источников

`check-sources` проверяет текущие разделы и извлекает ограниченную выборку текста. Отчёт находится в `source-checks.json` и `source-checks.md` внутри указанного runtime, примеры с полным текстом — в `source-checks/<source_id>/samples.jsonl`. Проверка сохраняет исходный DOM, но не скачивает картинки и не обходит архив. База рабочего корпуса не изменяется.

`passed` означает, что извлечено запрошенное число различных канонических статей, по умолчанию две. Одна статья — `partial`; блокировки, robots-запреты, отсутствие ссылок и ошибки текста отражаются отдельно. Проверка выборки не гарантирует полноту каждого материала или постоянную доступность сайта. Повторное продолжение: добавьте `--resume`; изменённые настройки проверяются заново. Подробнее — в [руководстве по эксплуатации](docs/OPERATIONS.md).


Для цепочки «новые статьи → индекс → приложение» используйте отдельный
[pipeline/live.py](../pipeline/LIVE.md). В collect/run доступен `--defer-images`:
сохраняются ссылки изображений без загрузки байтов. Этот режим не фильтрует новости
по наличию фото; robots/pacing/cooldown и runtime-lock сохраняются.
